Demo · 3 min · programa 1.3

El mismo prompt, dos resultados distintos

En directo
  1. Pega unas notas de reunión y pide: «Resume esta reunión y saca las tareas».
  2. Repite exactamente lo mismo en otro chat.
  3. Comparad: ¿mismo formato? ¿De dónde sale ese responsable? ¿Era una decisión o una propuesta?

Lo que falla

  • Formato distinto en cada ejecución.
  • Responsables y fechas inventados.
  • Cada persona escribe su propio prompt.
  • El conocimiento del equipo no está en ningún sitio.

Lo que aporta una skill

  • Instrucciones y criterios empaquetados.
  • Una plantilla que fija el formato.
  • Ejemplos y glosario que consulta cuando los necesita.
  • Un script que comprueba el resultado.
Usa las notas de references/ejemplos.md (v0.4 del kit): tienen una propuesta que parece decisión y una tarea sin responsable. Casi siempre una de las dos salidas inventa al responsable.
T2 · Anatomía de una skill

Una carpeta con cuatro tipos de pieza

SKILL.md
Lo lee

Cabecera (name, description) e instrucciones: alcance, pasos, reglas, excepciones. Obligatorio.

references/
Lo consulta

Documentación que lee solo cuando un paso lo pide: ejemplos, políticas, glosarios, catálogos.

assets/
Lo copia

Plantillas y ficheros que copia o rellena: .md con huecos, .docx corporativo, logos, esquemas JSON, tablas CSV.

scripts/
Lo ejecuta

Código para lo determinista: validar, calcular, convertir, generar ficheros. Solo su salida entra en contexto.

acta-reunion/                 ← el nombre de la carpeta = name
├── SKILL.md
├── references/  ejemplos.md · equipo.md
├── assets/      plantilla-acta.md
└── scripts/     validar_acta.py · exportar_acciones.py
Una skill no es solo lenguaje natural: lo que se puede fijar con una plantilla o comprobar con código, se fija y se comprueba.
Insiste en los cuatro verbos: lee, consulta, copia, ejecuta. Los usarán para decidir dónde va cada cosa durante todo el laboratorio.

  • Activa la ejecución de código: Settings › Capabilities (en Team y Enterprise lo habilita el administrador).
  • Comprime la carpeta, no su contenido.
  • Customize › Skills › + › Create skill › Upload a skill.
  • Team y Enterprise: Share o Publish to org.

T3 · GitHub Copilot

Copilot: VS Code, CLI y agente en la nube

Dónde y cómo

  • Proyecto: .github/skills/ (también lee .claude/skills/ y .agents/skills/).
  • Personal: ~/.copilot/skills/ o ~/.agents/skills/.
  • Funciona en VS Code, Copilot CLI, el agente en la nube y la revisión de código.
  • Crear en VS Code: Customizations › Skills › New Skill.
  • Invocación automática o /acta-reunion de la reunión de ayer.
  • Los ficheros se enlazan con rutas relativas al SKILL.md y solo se cargan si las instrucciones los citan.

Campos extra de la cabecera

---
name: acta-reunion
description: …
argument-hint: notas o transcripción
user-invocable: true            # sale en el menú /
disable-model-invocation: false # se activa sola
---

Otros arneses ignoran estos campos.

En un repositorio de código, .github/skills/ es lo natural si el equipo usa Copilot.

T3 · Skills de terceros

Repositorios de skills: úsalos, pero revisa siempre

skills.sh

Un directorio abierto, sin curar

  • Directorio abierto de skills con más de un millón publicadas.
  • Se instalan con npx skills add <propietario>/<repositorio>.
  • No están curadas: cualquiera publica, y una skill puede traer prompt injection en el SKILL.md o código malicioso en scripts/.
  • Revísalas SIEMPRE antes de instalarlas.
autoskills.sh

Detecta tu stack, skills curadas

  • npx autoskills en la raíz del proyecto: lee package.json, Gradle y otros ficheros de configuración y propone las skills tecnológicas que necesitas.
  • Sí están curadas: se revisan contra prompt injection y riesgos de cadena de suministro, y cada fichero se verifica con un hash SHA-256 al instalar.
  • --dry-run enseña qué instalaría sin instalar nada.
Instalar una skill es aceptar instrucciones y ejecutar código de otra persona. Antes de instalar: lee el SKILL.md entero, lee cada script, busca órdenes escondidas («ignora…», enlaces, curl … | sh) y pruébala en un proyecto vacío.
Dos minutos. Úsalo para conectar con el caso adversarial del paso 6: la misma prompt injection que puede venir en un CSV puede venir en una skill descargada.

El caso: el informe semanal de incidencias

La tarea

Cada lunes, Laura (responsable de soporte) exporta los tickets de la semana a un CSV y prepara un informe para dirección: resumen, críticas, horas y próximos pasos. Con la IA sale distinto cada semana.

Por qué merece una skill

  • Se repite cada semana.
  • Siempre se explica lo mismo: formato, criterios, cuentas.
  • Hay una forma correcta, y Laura la sabe.
  • Lo consume otra persona: dirección.
  • Riesgo bajo: Laura lo revisa antes de enviarlo.
